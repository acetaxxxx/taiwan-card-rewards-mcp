# 03: 統一交易記錄與時間查詢

**What to build:** 使用者以同一個 Transaction 寫入入口記錄信用卡、帳戶、錢包餘額或現金支出，並透過 `list_transactions` 依交易發生時間或記錄時間查詢歷史。回饋、上限、付款路徑與 FX 是可選的交易關聯資料，無回饋支出也能回溯。

**Blocked by:** 01: 確認新信任與交易語意.

**Status:** ready-for-agent

- [ ] Transaction 的 Funding Instrument 可表達信用卡、帳戶、錢包餘額與現金，且不再要求每筆交易都有 card ID。
- [ ] 每筆交易保留使用者指定的 `occurredAt` 與 MCP 自動寫入的 `recordedAt`；前者影響優惠、cap、FX 與旅程查詢，後者僅供稽核補登。
- [ ] `record_transaction` 維持 idempotency、退款關聯與實際金額的驗證；回饋未知不阻止一般交易記錄。
- [ ] `list_transactions` 支援起訖時間、`timeBasis`、穩定分頁、summary/detail 投影與目前使用者隔離；預設以 `occurredAt` 查詢，必要時可查 `recordedAt`。
- [ ] detail 結果能在需要時連結回饋、cap、付款路徑與已套用 FX，而不建立第二個公共記帳服務。
- [ ] 公開 MCP 整合測試涵蓋四種資金來源、晚間補登、兩種時間依據、時間邊界、分頁、退款、冪等性與租戶隔離。
