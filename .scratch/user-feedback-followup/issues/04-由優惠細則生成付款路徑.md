# 04: 由優惠細則生成付款路徑

**What to build:** 所有目前已知可付款的方法都可成為推薦候選。當優惠細則列出指定行動支付、受理網路、資金種類或必要轉折時，Agent 將完整清單寫入 Offer Route Selector，以判定該優惠是否適用；推薦再結合 selector、公共 Payment Capability 與使用者持有的卡片或帳戶，自動建立可比較的 Generated Route，而不要求預先登記每個組合。

**Blocked by:** 01: 確認新信任與交易語意.

**Status:** ready-for-agent

- [ ] Offer Rule 可表達可更新的支付服務 allowlist、受理網路、資金種類、節點角色與 Route Transition，且不引入品牌 enum。
- [ ] 細則的指定支付清單可在 ingestion 後成為 selector；未知或不完整清單不會被放大成所有服務都符合。
- [ ] Payment Capability 表達付款方式是否可形成路徑；Offer Route Selector 只表達特定優惠是否適用，兩者不可互相取代或混淆。
- [ ] `recommend` 能探索所有已知可付款方式，並由 selector、Payment Capability 與使用者持有事實建立 Generated Route；無優惠的可付款路徑仍可展示為候選，但不宣稱有回饋。
- [ ] Generated Route 僅用於 planned recommendation；使用者專屬綁定、實際觀察、專屬費率或否決才寫入 durable route。
- [ ] 測試驗證多支付服務清單、不同 funding、top-up 與 direct authorization 的差異、無優惠但可付款的候選，以及不符合 allowlist 的負向情境。
