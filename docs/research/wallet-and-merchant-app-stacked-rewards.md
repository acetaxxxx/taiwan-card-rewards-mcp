# 支付錢包與商家 App 綁定信用卡之回饋疊加模型研究

> **文件狀態**：Lead-reviewed research snapshot；供 `taiwan-card-rewards-mcp` 規則建模與 AI Agent 推薦使用之官方事實研究報告。
> **查詢日期**：2026-09-04
> **來源邊界**：本報告嚴格引用各支付平台、商家及銀行官方第一方公開條款與說明頁面。
> **研究目標**：建立台灣主流行動支付（全支付、LINE Pay、街口支付、橘子支付、Pi 拍錢包、悠遊付）與商家 App（王品瘋美食、skm pay 等）綁定信用卡後之回饋發放主體、疊加機制、排除通路、上限池與退款沖銷模型。

## 2. 回饋發放主體與多層疊加模型 (Multi-Layer Stacking Model)

當使用者透過第三方支付錢包或商家專屬 App 綁定信用卡進行消費時，回饋體系依權益提供方可拆解為三層：

```
┌─────────────────────────────────────────────────────────────────────────┐
│ Layer 1: 商家會員基本回饋 (Merchant Loyalty Layer)                        │
│   - 例如：王品瘋美食 App 會員出示會員碼 3% 瘋點數、新光三越 skm points      │
│   - 發放方：商家本身                                                    │
├─────────────────────────────────────────────────────────────────────────┤
│ Layer 2: 支付錢包通路加碼 (Payment Wallet Campaign Layer)                 │
│   - 例如：全支付筆筆加碼全點、悠遊付週五會員日 2%~5% 回饋金、街口支付活動街口幣│
│   - 發放方：電子支付機構 / 第三方支付業者                               │
├─────────────────────────────────────────────────────────────────────────┤
│ Layer 3: 發卡銀行信用卡原生回饋 (Card Issuer Reward Layer)                │
│   - 例如：國泰世華 CUBE 卡 (樂饗購/指定支付) 3% 小樹點、永豐 SPORT 卡 5% 豐點  │
│   - 發放方：發卡銀行                                                    │
└─────────────────────────────────────────────────────────────────────────┘
```

### 疊加組合類型：
1. **單一回饋 (Single Reward)**：僅享有發卡銀行原生回饋（如純以 LINE Pay 作為收單通道但無行銷活動）。
2. **雙重疊加 (Dual Stack)**：
   - **錢包加碼 + 信用卡原生回饋**：如街口支付綁定指定信用卡，同時獲得街口幣 + 信用卡現金/點數回饋。
   - **商家會員點數 + 信用卡原生回饋**：如新光三越出示會員累積 skm points 並刷聯名卡或高回饋卡。
3. **三重疊加 (Triple Stack)**：
   - 典型範例：至王品旗下餐廳用餐，出示王品瘋美食 App 累積 **3% 瘋點數**（Layer 1），使用「瘋 Pay」綁定指定銀行指定日加碼獲得 **3%~10% 瘋點數**（Layer 2），底層信用卡再觸發發卡行之餐飲或指定支付回饋（如國泰 CUBE 樂饗購 3% 小樹點）（Layer 3）。

## 3. 各大支付錢包與商家 App 官方規格剖析

### 3.1 全支付 (PXPay Plus)
- **官方來源**：[全支付點數與服務條款](https://www.pxpayplus.com/)
- **回饋主體**：全支付發放「全點」；若銀行有專屬合作（如玉山、國泰）則由銀行提供全點加碼或刷卡金。
- **支付路徑與指定卡**：
  - 於全聯門市使用全支付綁定信用卡，**多數銀行明確排除一般消費回饋**（視為全聯非一般消費通路）。
  - 於全聯外合作特店（如屈臣氏、手搖飲、網購）使用，銀行通常視為「一般消費」或「行動支付指定通路」。
- **上限與排除**：
  - 各合作銀行之全點加碼通常設有每戶每月上限，且活動總預算額滿即止（以 App 鈴鐺公告為準）。
  - 排除菸品、嬰兒配方食品、繳費等法定或約定不促銷項目。
- **退款機制**：退款時全額或依比例收回發放之全點；若全點餘額不足扣抵，系統自退款現金中扣除等值金額。

### 3.2 LINE Pay (連加網路)
- **官方來源**：[LINE Pay 官方服務條款](https://linepay.tw/)
- **回饋主體**：LINE Pay 平台活動發放 LINE POINTS；合作發卡行（如中信 LINE Pay 卡、富邦 J 卡、聯邦賴點卡）發放卡片約定之 LINE POINTS 或刷卡金。
- **疊加與路徑**：
  - LINE Pay 優惠券（折價券）通常與信用卡回饋同時生效（結帳金額扣除優惠券後之淨額計算刷卡回饋）。
  - 若活動要求指定卡別（如中信 LINE Pay 卡專屬活動），則須在 LINE Pay 內選用該卡結帳。
- **退款機制**：退款依退款金額比例收回 LINE POINTS；若點數已移轉或使用導致不足，自退款信用卡退稅/退刷金額中折抵扣除。

### 3.3 街口支付 (JKOPAY)
- **官方來源**：[街口支付使用者條款與街口幣規範](https://www.jkopay.com/)
- **回饋主體**：街口支付發放「街口幣」；台新街口聯名卡發放專屬街口幣加碼。
- **疊加與限制**：
  - 街口幣折抵：最高可折抵單筆交易金額 30%（部分專案活動可達 100%）。
  - 刷卡回饋計算：依折抵街口幣後的「實際信用卡刷卡授權金額」計算發卡銀行信用卡回饋。
  - 公共事業繳費（水電瓦斯、綜所稅）：多數信用卡將透過街口支付繳費列為「非一般消費」，僅少數特定卡片（或專案活動）給予回饋。
- **退款機制**：部分退款按比例收回街口幣；街口幣餘額不足者，自原信用卡退刷金額中直接扣抵。

### 3.4 橘子支付 (GamaPay)
- **官方來源**：[橘子支付最新活動與條款](https://www.gamapay.com.tw/)
- **回饋主體**：橘子支付發放 7-ELEVEN 零用金或橘子零用金（1 點 = NT$1）。
- **疊加與路徑**：
  - 支援綁定 VISA, MasterCard, JCB 信用卡。
  - 需完成實名認證與帳戶啟用（GamaPass）。
- **排除通路**：菸品、代收代付費用、代售商品。

### 3.5 Pi 拍錢包 (Pi Wallet)
- **官方來源**：[Pi 拍錢包點數回饋機制與最新公告](https://www.piapp.com.tw/)
- **回饋主體**：網路家庭 (PChome) / Pi 拍錢包發放「P 幣」；玉山 Pi 拍錢包信用卡發放 P 幣回饋。
- **捨入與計算規則**：自 2025 年 3 月 1 日起，P 幣回饋計算至新臺幣元，**小數點以下無條件捨去（Floor rounding），不足 1 點不予回饋**。
- **排除通路**：7-ELEVEN、全家便利商店、路邊停車費、水電瓦斯公用事業費用（自 2026/3/1 起多數繳費不再提供 P 幣回饋）。

### 3.6 悠遊付 (EasyCard Easy Wallet)
- **官方來源**：[悠遊付活動條款與回饋金規範](https://www.easycard.com.tw/)
- **回饋主體**：悠遊卡公司發放「悠遊付回饋金」至悠遊付電子支付錢包帳戶。
- **活動疊加機制**：
  - 「筆筆享回饋」常態活動 + 「週五會員日指定信用卡」加碼（例如 2%~5%）+ 指定發卡行生活繳費加碼。
- **上限控制**：每戶每月回饋上限，且具備全活動總預算額滿機制（可在 App 內「筆筆享回饋」專區查詢即時額滿進度）。

### 3.7 王品瘋美食 (瘋 Pay / 瘋點數)
- **官方來源**：[王品瘋美食官方條款與活動公告](https://www.wowprime.com/)
- **回饋主體**：王品集團發放「瘋點數」（1 點 = NT$1，效期 365 天）。
- **精確疊加與結帳程序**：
  1. **扣點**：若要折抵瘋點數，結帳前須先由店員掃描會員 QR Code 進行點數折抵。
  2. **累積發票金額 3%**：出示會員條碼享實付發票金額 3% 瘋點數（四捨五入）。
  3. **瘋 Pay 銀行日加碼**：以瘋 Pay 綁定合作銀行信用卡，依當日銀行加碼（如 +3%~10%）額外獲贈瘋點數。
  4. **信用卡原生回饋**：依底層信用卡權益（如國泰 CUBE 卡 樂饗購 3%）再享銀行點數/現金回饋。
- **額滿狀態**：各銀行加碼名額每日於 App 內 10:30 更新額滿狀態（顯示 100% 即額滿）。

### 3.8 skm pay (新光三越)
- **官方來源**：[新光三越 skm pay 說明](https://www.skm.com.tw/)
- **命名釐清 (Disambiguation)**：使用者所稱之「Sky Pay」在台灣消費金融場景中，為新光三越百貨行動支付 **「skm pay」** 之常見口語稱呼。
- **回饋主體**：新光三越發放 skm points，發卡銀行提供百貨刷卡滿額禮或聯名卡點數。
- **通路特性**：封閉型百貨專屬支付，屬於百貨特店消費，信用卡回饋需檢核是否符合「百貨消費」或「行動支付」定義。

## 4. 系統規則建模與 Invariants (MCP Evaluator 實作指引)

為使 `taiwan-card-rewards-mcp` 支援上述錢包與商家 App 疊加模型，規則引擎應遵循以下不變量：

1. **MCC 與 Payment Method 雙重檢核**：
   - 錢包交易的交易型態屬 `paymentMethods: ['pxpayplus', 'linepay', 'jkopay', 'gamapay', 'piapp', 'easywallet', 'wowpay', 'skmpay']`。
   - 規則必須能同時匹配 `merchant`（如 "全聯", "王品牛排"）、`mcc` 與 `paymentMethod`。
2. **扣除點數折抵後之淨額計算 (Net Spend Basis)**：
   - 若交易包含錢包點數折抵（如街口幣、瘋點數、全點），發卡銀行信用卡之回饋計算基準必須為**扣除點數折抵後由信用卡實際扣款之金額 (`settlementAmountMinor`)**。
3. **多上限池獨立扣抵 (Independent Cap Pools)**：
   - 錢包加碼活動上限（通常為每月/每活動期間固定點數）與銀行信用卡自身上限（如每月 500 元）為**獨立 Cap Pools**，不可混用。
4. **排除通路 Fail-Closed 判定**：
   - 便利商店（7-11, 全家）與全聯等通路在多數信用卡被列為 Exclusion，除非信用卡規則明確宣告包含該 Payment Method 或特約通路加碼，否則預設判定為不適用或 `needs_review`。
5. **資料新鮮度與額滿狀態 (Provenance & Quota Freshness)**：
   - 支付活動（如瘋 Pay 每日限量、悠遊付額滿）具有動態性。若活動註明「額滿為止」且無即時狀態 API，系統評估時應標示 `availableAfterActions` 或警示 `conditional: true`，提示使用者確認當日名額。

## 5. 不確定性與後續維護清單

1. **銀行一般消費排除清單變動**：各發卡行每半年（1/1 與 7/1）調整電子支付與超商排除清單，需持續更新官方 source snapshot。
2. **活動額滿即時性**：多數電支活動額滿公告僅呈現在 App 內部（如全支付小鈴鐺、悠遊付首頁），無法由靜態網頁實時抓取，AI Agent 需提醒使用者留意 App 內即時額滿指示。
3. **退款扣回溢額處理**：若使用者點數不足扣抵，各家電支扣回現金之機制不一，在帳本記帳時應以原始交易所關聯之交易紀錄為準。
